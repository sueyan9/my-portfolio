# UI Design Checklist

将适用内容写入当前变更的 `design.md`，保留标准设计章节；不适用项注明原因。

## Context

- 用户目标、当前问题、涉及路由与组件。
- 改动前截图或代码位置；参考图/设计稿链接及采用的具体特征。

## Goals / Non-Goals

- 本次视觉与交互目标、范围，以及明确保留的行为。

## Decisions

- 布局：内容顺序、宽度、间距、对齐、层级。
- 视觉：字体、字号、颜色变量、边框、圆角、阴影；优先复用现有样式。
- 交互：默认、悬停、焦点、选中、禁用，以及适用的加载/空/错误状态。
- 动效：触发方式、时长、退出方式、减少动态效果偏好的处理。
- 响应式：手机、平板、桌面布局；写明采用的断点及原因。
- 可访问性：键盘顺序、可见焦点、语义标签、替代文本、对比度。
- 方案取舍：选择原因、考虑过的替代方案、影响文件和依赖。

## Risks / Trade-offs

- 对其他页面、性能、内容长度或现有交互的影响。

## Verification

- 将可观察的验收行为写入对应 specs 的 Requirement / Scenario。
- 记录实际检查的桌面与手机视口尺寸、浏览器、键盘及触摸交互结果。
- 链接 `assets/` 中的改动前后截图，注明页面、视口和状态。
- 记录 build / lint 结果；未执行或未验证的内容明确标注。

## Open Questions

- 未定决策及其影响；确认后在此记录结论。
